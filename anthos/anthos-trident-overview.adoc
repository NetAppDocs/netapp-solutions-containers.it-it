= Panoramica Trident
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Trident è un orchestratore di storage open source completamente supportato per container e distribuzioni Kubernetes, tra cui Anthos.  Trident funziona con l'intero portfolio di storage NetApp , incluso NetApp ONTAP, e supporta anche connessioni NFS e iSCSI.  Trident accelera il flusso di lavoro DevOps consentendo agli utenti finali di effettuare il provisioning e gestire lo storage dai propri sistemi di storage NetApp senza richiedere l'intervento di un amministratore dello storage.

Un amministratore può configurare una serie di backend di archiviazione in base alle esigenze del progetto e ai modelli di sistema di archiviazione che abilitano funzionalità di archiviazione avanzate, tra cui compressione, tipi di dischi specifici e livelli QoS che garantiscono un certo livello di prestazioni.  Una volta definiti, questi backend possono essere utilizzati dagli sviluppatori nei loro progetti per creare richieste di volume persistenti (PVC) e per collegare storage persistente ai loro contenitori su richiesta.

image:a-w-n-astra-trident.png["Figura che mostra il dialogo di input/output o che rappresenta il contenuto scritto"]

Trident ha un ciclo di sviluppo rapido e, come Kubernetes, viene rilasciato quattro volte all'anno.

Consulta la link:https://docs.netapp.com/us-en/trident/index.html["Documentazione Trident"^] per le informazioni sulla versione più recente. Una matrice di supporto per la compatibilità delle versioni di Trident con le distribuzioni Kubernetes è disponibile in link:https://docs.netapp.com/us-en/trident/trident-get-started/requirements.html#supported-frontends-orchestrators["Frontend supportati (orchestratori)"^].

A partire dalla versione 20.04, la configurazione Trident viene eseguita dall'operatore Trident .  L'operatore semplifica le distribuzioni su larga scala e fornisce supporto aggiuntivo, tra cui l'auto-riparazione per i pod distribuiti come parte dell'installazione Trident .

Con la versione 22.04 è stata resa disponibile una tabella Helm per semplificare l'installazione del Trident Operator.

Vedi link:https://docs.netapp.com/us-en/trident/trident-install/kubernetes-deploy.html["Dettagli sull'installazione di Trident"^] per maggiori informazioni.



[[create-a-storage-system-backend]]
== Creare un backend del sistema di archiviazione

Dopo aver completato l'installazione di Trident Operator, devi configurare il backend per la specifica piattaforma di storage NetApp che stai utilizzando. Segui il collegamento qui sotto per continuare la configurazione di Trident. link:https://docs.netapp.com/us-en/trident/trident-use/backends.html["Crea un backend"^]



[[create-a-storage-class]]
== Creare una classe di archiviazione

Dopo aver creato il backend, devi creare una classe di storage che gli utenti di Kubernetes specificheranno quando vogliono un volume. Gli utenti di Kubernetes effettuano il provisioning dei volumi usando le persistent volume claim (PVC) che specificano una classe di storage per nome. Segui il link qui sotto per creare una classe di storage. link:https://docs.netapp.com/us-en/trident/trident-use/create-stor-class.html["Creare una classe di archiviazione"^]



[[dynamically-provision-a-volume]]
== Fornire dinamicamente un volume

Devi creare un oggetto Kubernetes Persistent Volume Claim (PVC) utilizzando la classe di storage per eseguire il provisioning dinamico di un volume. Segui il link qui sotto per creare un oggetto PVC. link:https://docs.netapp.com/us-en/trident/trident-use/vol-provision.html["Creare un PVC"^]

== Usa il volume
